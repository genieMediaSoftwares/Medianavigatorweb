# Media Navigator — A-Z Scratch to Production Project Tracker Guide

This document and the companion file `PROJECT_TRACKER_SPREADSHEET.tsv` serve as the **master reference framework** for tracking social media intelligence, analytics platforms, and enterprise full-stack web applications from initial conception to production deployment.

You can copy and paste the contents of `PROJECT_TRACKER_SPREADSHEET.tsv` directly into **Google Sheets**, **Microsoft Excel**, or **Airtable**.

---

## 1. Spreadsheet Structure & Column Schema

The tracking spreadsheet uses a 12-column standardized layout designed for engineering teams, project managers, and executive stakeholders:

| Column | Name | Purpose & Values |
| :--- | :--- | :--- |
| **A** | **Module** | Functional division (`Planning`, `Backend`, `Analytics`, `AI Engine`, `Frontend`, `Testing & QA`, `Security`, `Deployment`, `Documentation`) |
| **B** | **Subcategory** | Sub-system or component domain (e.g. `YouTube Integration`, `Timing Intelligence`, `State Management`) |
| **C** | **Task ID** | Unique ticket identifier (e.g. `MN-001` through `MN-045`) |
| **D** | **Task Description** | Clear, actionable definition of what was engineered |
| **E** | **Assignee** | Role accountable (`Product Architect`, `Lead Engineer`, `Backend Lead`, `Frontend Lead`, `AI Engineer`, `DevOps Engineer`, `QA Engineer`, `Security Lead`) |
| **F** | **Priority** | Urgency & impact level (`High`, `Medium`, `Low`) |
| **G** | **Status** | State of work (`Completed`, `In Progress`, `Pending`, `Blocked`) |
| **H** | **Phase** | Delivery milestone phase (`Phase 1: Specs & Design` through `Phase 7: QA & Production`) |
| **I** | **Est. Days** | Engineering effort estimate in developer days |
| **J** | **Completion %** | Quantitative completion progress (`0%` to `100%`) |
| **K** | **Deliverables / Acceptance Criteria** | Concrete verification criteria (e.g. specific files created, tests passing, endpoints active) |
| **L** | **Notes & Architecture References** | Key engineering context, edge case solutions, and file paths |

## 2. Phase-by-Phase Roadmap (A to Z)

### Phase 1: Product Specifications & Architecture Design (Tasks MN-001 – MN-002)
- **Goal**: Lock down product requirements, user journeys, zero-hallucination ground rules, and strict TypeScript contracts.
- **Key Deliverables**:
  - `PRD.md` (Product Requirements Document covering all 14 functional modules).
  - `SPECIFICATIONS.md` (Technical architecture, API table, component tree).
  - `shared/types.ts` (`NormalizedMedia`, `PlatformConnection`, `PerformerAnalysis`, `Recommendation`, `TimingSlot`).

### Phase 2: Core Server & State Management (Tasks MN-003 – MN-004)
- **Goal**: Establish the runtime environment and an in-memory aggregation store with secure credential isolation.
- **Key Deliverables**:
  - `server.ts` Express application mounted on port 3000 with Vite middleware in development and static SPA serving in production.
  - `backend/src/services/dataStore.ts` with private `credentialsVault` ensuring credentials are never transmitted to client payloads.

### Phase 3: Platform Ingestion & Data Normalization (Tasks MN-005 – MN-010)
- **Goal**: Integrate live platform APIs across YouTube, Instagram, Facebook, and LinkedIn with universal data normalization.
- **Key Deliverables**:
  - `youtubeClient.ts` & `dataApi.ts`: Supports handle lookup (`@handle`), channel ID (`UC...`), and auto-discovery via `videos?chart=mostPopular`.
  - Recursive playlist fetcher parsing ISO 8601 durations and categorizing Shorts (`<=60s`) vs. Long-form video (`>60s`).
  - `instagramClient.ts` & `metaAuth.ts`: Dual-endpoint support (`graph.instagram.com` and `graph.facebook.com`) for Reels, Carousels, and Posts.
  - Universal normalization pipeline converting all heterogeneous items to `NormalizedMedia` with strict engagement rate formula:
    $$\text{Engagement Rate} = \frac{\text{Likes} + \text{Comments}}{\max(\text{Reach}, \text{Views})} \times 100$$

### Phase 4: Statistical Analytics & Pattern Engine (Tasks MN-011 – MN-015)
- **Goal**: Transform raw media counts into executive intelligence without synthetic placeholders.
- **Key Deliverables**:
  - Top 5 and Bottom 5 Performer ranking engine calculating exact ratio to channel median (e.g. `2.4x baseline`).
  - 7x4 Day-and-Hour Publication Timing Heatmap matrix (28 time slots normalized 0–100 with sample counts).
  - Complete Content Archive Audit computing format distribution percentages.
  - Question Hook Delta measuring engagement lift generated by interrogative caption hooks (`?`).
  - Velocity Curves engine comparing recent half of catalog against earlier half to detect momentum shifts.

### Phase 5: Grounded AI Intelligence & Gemini Copilot (Tasks MN-016 – MN-019)
- **Goal**: Provide conversational intelligence and post diagnostics strictly anchored in verified archive numbers.
- **Key Deliverables**:
  - Integration of Google Gen AI SDK (`@google/genai`) running `gemini-3.8-flash`.
  - "Ask Media Navigator" (`POST /api/v1/intelligence/ask`) injecting full archive audit context into system prompt.
  - Deep-dive AI Post Diagnosis modal with 5-dimension scorecard (hook, pacing, retention, distribution).
  - 5-Point Strategic Recommendation Engine (Problem, Pattern, Improvement, Script Hook, Measurement).

### Phase 6: Frontend UI/UX & Responsive Client Layer (Tasks MN-020 – MN-035)
- **Goal**: Deliver a polished, high-contrast, production-grade responsive web interface adhering to strict anti-slop guidelines.
- **Key Deliverables**:
  - `MediaContext.tsx` centralized reactive state with zero mock data and typed `api.ts` client.
  - 12 Core App Pages: Overview, Content Intelligence, Intelligence Hub, Recommendations, Timing Heatmap, Trends, Content Planner, Cross-Platform Matrix, Executive Reports, Connections Hub, Alerts Center, and Settings.
  - High-conversion Landing Page, Sign-In with 1-click Demo Workspace access, and 3-step Onboarding wizard.

### Phase 7: Quality Assurance, Security & Production Deployment (Tasks MN-040 – MN-045)
- **Goal**: Validate zero mock data, verify API error resilience, harden security, and prepare production deployment.
- **Key Deliverables**:
  - Zero mock data guarantee: clean transparent empty states when accounts are not connected.
  - 100% strict read-only OAuth permission audit.
  - Clean TypeScript compilation (`tsc --noEmit`) and Vite production bundle optimization.
  - Production container scripts (`npm run build`, `npm run start`).
